Two deliberate changes from the CLAUDE.md order: the critique runs after render so Haiku can look at the actual PNG, and cheap code checks (lengths, exclamation marks, banned terms, exact quote, overflow) run before it so the model doesn't have to count characters. With source and version bookkeeping stripped, generation context is about 4,300–6,000 tokens per intent (visual-system.json alone is ~800), so the spike loads full profiles and shows the size on the review page rather than dropping chunks. Tested end to end against a mock API; no real posts yet.

- 2026-11-03: Phase 3 scaffold. Next.js 16 (App Router) at the repo root for Netlify; the spike's pure code (model config, chunk selection, prompt filling, schemas, the Claude call) moved to `core/` so the app reuses it unchanged, and a build step bundles `prompts/`, `templates/` and the demo kit into a server-only module because Netlify functions don't ship files read from disk. The server owns every prompt: routes take strict structured fields, refuse anything named like a prompt or model setting (`raw_prompt_refused`), and escape free text before it enters the `<brief>` block. Every guard in the spec's table that lives in code is in, with 17 tests. Three things the platform forced: (1) Netlify ends a function at 60 seconds, so plan and write are separate requests, with the plan kept server-side so the browser can't swap it; (2) Netlify's request limit is about 4.5 MB, below the spec's 5 MB photo cap, so phase 4 should shrink photos in the browser before upload; (3) Netlify's own docs warn against counters on Blobs, so the tripwire reserves each call's worst case (estimated input plus every allowed output token) with compare-and-swap writes, then settles at the real cost. Any race overcounts, and the Console workspace's monthly limit sits behind it. The app runs plan and write but not yet critique, which reads the rendered PNG; it returns once posts render in the browser. `npm run gate` checks the phase 3 gate against the deployed site for free.
- 2026-11-03: **Phase 3 gate passed** on the deployed site (rainbow-souffle-b79aad.netlify.app): `npm run gate` refused raw prompts, model overrides, prompts hidden in the brief, a 501-character message, an 11-page PDF, a 5 MB+ photo and a non-image file, and, after the day's real spend passed a lowered cap, every new session, post and write (503 `daily_cap_reached`). Two things the first deploy taught: (1) every storage read hung for 30 seconds and ended in a 504, because Netlify Blobs was calling through the `fetch` Next.js wraps; Blobs now uses the original fetch with a 4 s per-attempt and 12 s per-operation limit and logs failures. (2) The function is cut off at about 30 seconds, not the 60 in Netlify's docs, so Claude calls time out at 26 s. Real timings on the first four live posts: plan 12–18 s, write 8–15 s, four posts for a little under 30 cents. The session cap (4 posts) stopped the test before the spend cap did, so the tripwire was checked by lowering the cap below what had already been spent that day.
- 2026-11-03: Phase 4 build: extraction and the Brand DNA reveal. Scott asked whether to define the app's styling now; no: the spec gives the app's look to the A2UI catalog (phase 5) and the app's own brand kit (phase 6), so the reveal stays plain. Extraction runs in two steps because the deployed function is cut off at about 30 seconds and one call can't read every upload and write eleven chunks in that time: (1) **read**, one call per upload (photo, logo, PDF, website through Claude's web fetch tool limited to that site and three pages, pasted site text, the note), each returning evidence notes with where they came from; (2) **assemble**, one call per kit chunk plus one that only looks for disagreements, all reading the same evidence as cached text so only the first pays full price for it. The browser runs the calls and shows each as it lands, which is the reveal. Photos are shrunk in the browser to fit under Netlify's upload limit, and their main colors are sampled there in code; the model may only use a hex value that an upload writes out or that a photo sample supports, and anything else is kept but marked needs-review. Items citing an upload that doesn't exist are dropped. Every item can be edited or deleted for free. Two additions not in the spec's caps table: a paste box (8,000 characters) as the fetch fallback the spec's Decisions mention, and two tries per extraction call. Found and fixed a phase 3 bug while testing: a post whose Claude call timed out after billing was refunded to the session; it now counts. The gate check is `npm run spike -- spike/extract.ts half-acre-club`: a 20-item checklist from the messy uploads (including the "BOX No. 014" conflict, and three things it must not invent: a price, the founder, the city, which came from Scott, not the uploads) plus a side-by-side with the hand-built kit and per-call timings. Not yet run with a real key. Expected cost per extraction is about $0.30–0.50, so a full live session (extraction plus four posts) is nearer $0.60–0.80 than the spec's $0.30–0.50.
